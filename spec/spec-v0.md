# Задача - создать cli shell утилиту/скрипт `Markdown Link & Dead Code Checker`

## Технический стек:

Язык: Python (установленная версия)
Tools: uv (установленная версия), pytest, ruff
Библиотеки: предпочтительно использовать stdlib. Все необходимые сторонние библиотеки записать в requirements.md

## Функциональная часть

1. Рекурсивно сканирует файлы с расширением `.md` директории указанной через параметр командной строки `--workdir` (по умолчанию текущей рабочей директории - `./`).
 - Ищем патерны ссылок `[текст] (url)` и `file:///...` и извлекаем ссылки.
2. Рекурсивно Проходим весь полученный список ссылок и проверяем доступность ресурсов. Для ссылок проверяем доступность через отправку HTTP HEAD запроса статус, успешным считаем статус код 200, следуем 3xx для получения конечного статуса. Для файла просто проверяем существует ли конечный файл, если файл является ссылкой, то проверяем существует ли конечный файл. Относительные пути к файлам расчитывается от пути md файла в котром ссылка обнаружена. Все ссылки со статсусами заносим в Map.
  - Для файлов так как проверяем только наличие статус код для файлов которые не найдены - `n/a`.
  - Для http запросов нужно определить, что код не падает с ощибкой при получении статус кода не 200.
  - Для реез запросов нужно определить таймаут.
3. После выполнения выводим форматированную таблицу со сломанными ссылками в формате:
```
| Текст ссылки | Ссылка | Файл-Источник | Статус |
|--------------|--------|---------------|--------|
```
Под таблицей - общая статистика по обработанным ссылкам/файлам - сколько всего, сколько здорово, сколько сломано.

## Правила проекта

1. Для установки библиотек используй uv.
2. Весь код в одном файле `linckchecker.py`
3. Весь output строго на английском.
4. Не нужно генерировать коментарии.
5. Работает строго в иницированом venv. Активация venv `source .venv/bin/activate`
6. Каждая функция должна иметь минимум один тест кейс.

## Приёмка

1. Зелёный результат выполнения `ruff check --fix .` -> `All checks passed!` и exit code == 0 
2. Зелёный результат выполнения `pytest` -> exit code == 0
3. Зелёный прогон на директории с тестовыми данными. `./linckchecker.py --workdir ~/aihome/ecto-1-kb`

При провале результат выполнения передаётся на input итерации до устранения ошибки но не более 15.
